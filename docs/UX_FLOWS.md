# StoryVital — 디테일 플로우 점검 & 이탈 방지 (2026-08-01)

> 사용자의 실제 동선을 따라가며 ① CRUD 버튼 누락, ② 이탈(포기·데이터 손실) 지점을 전수 점검하고 개선한 기록.
> 원칙: **"입력한 것은 절대 잃지 않는다 · 만든 것은 반드시 수정/삭제할 수 있다 · 다음 행동이 항상 보인다"**

## 1. CRUD 매트릭스 (점검 전 → 후)

| 대상 | 생성 | 조회 | 수정 | 삭제 | 저장 |
|---|---|---|---|---|---|
| 캐릭터 | ✅ | ✅ | ✅ 카드/상세/딥링크 | ❌→✅ 상세 패널에도 추가 | ❌→✅ localStorage |
| 관계(+친밀도) | ✅ | ✅ 관계도 | ✅ | ✅ | ✅ |
| 회차 | ✅ | ✅ | **❌→✅** (상태 변경 포함) | **❌→✅** (연결 복선 함께 정리) | **❌→✅** localStorage |
| 복선/사건 | ✅ | ✅ | **❌→✅** | **❌→✅** | **❌→✅** localStorage |
| 작품(index) | ✅ | ✅ | ❌ (미해결) | ❌ (미해결) | △ 활성 ID만 저장 |

## 2. 발견된 이탈 지점과 조치

### 🔴 치명 — 데이터 손실 (이탈 확정 요인)
| 지점 | 문제 | 조치 |
|---|---|---|
| chapters 전체 | 저장 로직이 아예 없어 **새로고침 = 전부 소실**. 회차를 쌓던 사용자가 돌아왔을 때 빈 화면 → 즉시 이탈 | `sv_chapters_{workId}` / `sv_threads_{workId}` localStorage 영속화 |
| 회차 상태 변경 불가 | "집필 예정→집필 중→연재됨" 진행 표시가 서비스 핵심인데 생성 후 변경 불가 | 회차 수정 모달(상태 포함) 추가 |
| 폼 드로어 실수 닫기 | 캐릭터 정보를 길게 입력하다 오버레이 클릭/ESC → 전부 날아감 | 새 캐릭터 작성 중 내용이 있으면 닫기 전 확인 |

### 🟡 마찰 — 누적되면 이탈
| 지점 | 문제 | 조치 |
|---|---|---|
| 관계 이름 입력 | 한 글자 입력마다 재렌더링으로 포커스 상실 (한 글자씩만 입력 가능한 버그) | 재렌더링 제거, 아바타 이니셜만 갱신 |
| 관계 이름 오타 | 오타가 그대로 유령(미등록) 노드가 됨 | 기존 캐릭터 이름 **자동완성(datalist)** 제공 |
| 관계도→편집 동선 | "편집" 클릭 시 캐릭터 목록으로만 이동, 다시 찾아야 함 | `characters.html?edit={id}` 딥링크 — 해당 인물 편집 드로어 즉시 오픈 |
| 유령 노드 막다른 길 | 미등록 인물 클릭 시 안내만 있고 행동 버튼 없음 | "캐릭터 DB에 등록하기" CTA로 변경 |
| 데모 데이터 혼동 | 예시 인물이 내 데이터처럼 보임, 지울 방법 없음 | 데모 배너 + "비우고 시작" 버튼 (비운 상태는 유지됨) |
| 회차 모달 초기화 | 이전 입력값이 남은 채 열림 | 열 때마다 리셋, 수정 모드는 기존 값 채움 |
| 빈 회차 상태 | 회차 전부 삭제 시 이전 상세가 그대로 남음 | 빈 상태 안내 + "회차 추가" 유도 문구 |
| 키보드 동선 | ESC로 모달/패널을 닫을 수 없음 | 전 페이지 ESC 지원 (작성 중이면 확인 후) |

### 🎨 감성 — "이름만 있으면 재미없다"
| 지점 | 조치 |
|---|---|
| 캐릭터가 텍스트뿐 | **아바타 시스템**: ① 이름을 시드로 한 샘플 6종(스타일별) 자동 생성, 🎲로 다시 뽑기 ② **사진 직접 업로드** (128px 축소·JPEG 압축 → localStorage 안전) ③ 기본(이니셜) 복귀 |
| 표시 위치 | 캐릭터 카드 · 상세 패널 · 관계 목록 · **관계도 그래프 노드**(원형 클립 + 캐릭터 색상 링) 전부 반영 |

## 3. 로그인·대시보드 플로우 재설계 (2026-08-02)

**문제**: Firebase 미설정 상태에서 `onAuth`가 항상 "미로그인"을 반환 → 대시보드에 들어올 때마다 로그인 화면으로 튕김. "로그인 없이 체험하기"는 새로고침마다 리셋되는 가짜 데이터였음.

| 조치 | 내용 |
|---|---|
| **필명 로그인 도입** | 로그인 화면에서 필명 입력 → `sv_user`에 프로필 저장. 이후 방문 시 **로그인 화면을 거치지 않고 바로 대시보드**. Google 로그인은 Firebase 연동 후 활성화되는 보조 수단으로 유지 (실패 시 안내 문구) |
| **로그인 필수화** | 체험(데모) 모드 제거. 모든 페이지(캐릭터/관계도/챕터/내보내기)에 가드 추가 — 프로필 없이 접근하면 로그인으로 이동 |
| **대시보드 실데이터 연동** | 작품 목록 `sv_works` 영속화, 캐릭터·회차·복선 수치를 실제 localStorage 데이터에서 집계. 작품 전환 시 즉시 반영 |
| **데이터 실종 방지** | 온보딩에서 첫 작품 생성 시, 그 전에 `default` 키로 저장했던 캐릭터/회차를 새 작품으로 자동 이전 |
| **스트릭 재정의** | 기존 "집필 스트릭"은 글자 수를 매일 손으로 입력해야 채워지는 구조 + 시간대 버그(UTC 날짜) → **"기록 스트릭"**으로 재정의: 캐릭터·회차·복선·집필량 등 **무엇이든 기록한 날**이 자동으로 채워짐 (`sv_record_days`). 범례·툴팁·"연속 기록" 문구로 통일. 서비스 본질(꾸준한 설정 기록)과 일치 |

## 4. 작품 관리 & 설정집 내보내기 (2026-08-02, 2차)

| 조치 | 내용 |
|---|---|
| **작품 수정/삭제** | 대시보드 작품 카드에 수정 버튼 추가 → 모달에서 제목·장르·상태·일일 목표·진행도(%) 수정, 삭제 버튼 포함. 삭제 시 연결된 캐릭터/회차 개수를 보여주고 확인 후 해당 데이터까지 정리. 마지막 작품 삭제 시 온보딩으로 자연 복귀 |
| **설정집(Story Bible) TXT** | export 페이지에서 현재 작품의 캐릭터(프로필·관계·친밀도)·회차·복선을 정리한 설정집 텍스트 다운로드 — 피칭/공유용. "설정의 자산화" 가치의 첫 구현 |
| **JSON 백업/복원** | 작품 전체 데이터를 JSON 파일로 다운로드, 다른 브라우저/기기에서 가져오기로 복원 (덮어쓰기 전 확인). localStorage 유실 리스크에 대한 안전망 |

## 5. Firebase 연동 정비 & 첫 진입 안정화 (2026-08-02, 3차)

| 발견 | 조치 |
|---|---|
| **file:// 치명 버그**: index.html의 `./firebase.js` 정적 import가 file://에서 차단 → 대시보드 JS 전체 사망(필명 로그인조차 불가) | 동적 import + 실패 허용으로 전환 — 더블클릭으로 열어도 필명 로그인·로컬 모드 완전 동작 |
| Google 로그인 불가 원인 = **Firebase 미연동** (설정값이 자리표시자) | `isConfigured` 플래그 도입: 미연동이면 Google 버튼 반투명 + 클릭 시 설정 가이드 안내. [FIREBASE_SETUP.md](./FIREBASE_SETUP.md) 단계별 가이드 작성 |
| 설정이 3곳에 중복 (firebase.js + characters + chapters 인라인) → 키를 넣어도 반쪽 연동 | **firebase.js 한 곳으로 통일** — 키 한 번 붙여넣으면 전 페이지 적용 |
| Auth 구독이 예외를 던지면 이후 스크립트 중단 가능 | try/catch로 감싸고 로컬 모드 폴백 |

## 6. 남은 항목 (다음 라운드)
1. 삭제 후 **실행 취소(Undo) 토스트** — confirm보다 부드러운 이탈 방지 패턴
2. 사진 업로드는 localStorage 한정 (Firebase 연동 시 Storage로 이전 필요)
3. 모바일에서 관계도 정보 패널이 화면을 가리는 문제 검토
4. Firebase 연동 시: 필명 프로필 → Google 계정으로 데이터 승계 플로우 설계
5. 사건 타임라인 (WP-5 잔여) — 작중 시간 기준 사건 배치 + 인물 연결
6. 설정집 PDF 버전 (IP Bible 수익 모델의 기반)
